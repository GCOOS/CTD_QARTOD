# WS24258 CNV and QC configuration

This directory is the dataset-owned configuration for the WS24258 cruise.
`cnv_mapping.json` was generated by inspecting all 90 CNV files in the cruise;
88 files declare data and two are incomplete header-only files.

## Current status

- `cnv_mapping.json` maps all 24 science sources from their stable CNV comments;
  no valid-file entry remains in `review`. The inspection report records
  `ws24258_stn.053.cnv` and `ws24258_stn.056.cnv` as missing `nquan`,
  `nvalues`, and data rows.
- Stable source units are present in `attributes.units`. Reviewed equivalent
  spellings are used for CF-facing output, while conversion records the CNV
  spelling in `source_units`. CF standard-name URLs are generated from table
  v94.
- Every QC-selected variable has an exact sensor tag or is explicitly marked
  `derived`. The generated sensor files cover 15 variables and 11 physical or
  derived sensor groups; all range limits remain `null` for human completion.
- `flSP`, `flag`, and `pumps` declare no source unit. Of these, only the
  QC-selected `fluorescence_seapoint` needs a unit decision before a gross
  range can be configured.
- Spike limits, rate-of-change limits, climatology, station coordinates,
  location tolerance, and publication-level global metadata remain empty or
  disabled until scientifically reviewed for WS24258.
- Flat-line settings retain the project template values and should be reviewed
  before the first production QC run.

## Verified workflow

Run commands from the repository root:

```bash
PYTHONPATH=. uv run python main.py convert-cnv \
  '/Volumes/Crucial X9/CTD_QARTOD/cnv_data/WS24258' \
  --mapping config/ws24258/cnv_mapping.json \
  --output output/WS24258_CNV

PYTHONPATH=. uv run python main.py generate-sensor-config \
  --profile config/ws24258/dataset_profile.json

PYTHONPATH=. uv run python main.py qc \
  --profile config/ws24258/dataset_profile.json
```

The end-to-end verification converted 88 valid casts and QC wrote 88 outputs
with zero failures. Conversion deliberately reports the two incomplete source
files as failures and creates no empty profiles for them. Source NetCDF is
under `output/WS24258_CNV`; duplicate-mode QC preserves it and writes under
`output/WS24258_QC`.
